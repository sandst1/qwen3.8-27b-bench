# notify-digest

A small cron job that pulls a handful of feeds, filters the items per channel,
and sends each channel a digest.

## Running

```sh
cp config.example.toml config.toml
python3 digest.py --config config.toml --db digest.sqlite3
```

`--dry-run` prints what would be sent instead of sending it.

Requires Python 3.11+ (uses `tomllib`). No third-party dependencies.

## Layout

| File | Purpose |
| --- | --- |
| `digest.py` | CLI entry point, the per-run loop |
| `feeds.py` | Fetching and normalising the three feed formats |
| `store.py` | SQLite archive of everything seen + delivery dedup |
| `render.py` | Digest text |
| `channels.py` | Delivery (stdout, webhook) |

## Dedup

Cron runs `digest.py` every 15 minutes, but feeds don't produce fresh items
every 15 minutes — most polls see mostly-the-same content. `store.py` keeps
a `deliveries` table of (channel, link) pairs already sent, and `digest.py`
filters each channel's matched items through `store.undelivered()` before
rendering/sending, then calls `store.mark_delivered()` only after
`channels.send()` succeeds (so a channel outage means a retry next tick,
not a lost item).

Item identity for this is the item's `link`, not `raw_id`: the "blogroll"
feed format has no id at all, and the "generic" format's guid is
regenerated by the provider on every edit (typo fixes, retitles). `link` is
the only field that's both present and stable across all three formats.
One consequence: if a provider changes an article's URL, it will look like
a brand-new item and go out again — that's a deliberate tradeoff, not a
bug, given what identifiers these feeds actually give us.

`--dry-run` never touches `deliveries`, so previewing a digest doesn't
consume an item's one delivery.

The `fixtures/` directory holds two snapshots of the feeds taken at different
times, so you can work on this without network access. Point the config at
`snapshot-a` or `snapshot-b`.

## Deployment

Runs from cron on the utility box:

```
*/15 * * * * cd /srv/notify-digest && python3 digest.py >> /var/log/digest.log 2>&1
```
